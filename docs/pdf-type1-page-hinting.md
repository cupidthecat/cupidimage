# PDF Type 1 page hinting

`--pdf-type1-hinting` enables the bounded Type 1 fitting profile. The API
equivalent is `cupidimage_pdf_options.type1_hinting = 1`. Combine it with
`--pdf-text-aa` for grayscale fills. Both options are off by default. TrueType
and CFF have separate hinting switches.

The option applies to supported embedded Type 1 programs. It uses the native
font parser, charstring interpreter and [hint-data capture](pdf-postscript-hints.md),
with the [bounded grid-fitting core](pdf-postscript-gridfit.md). No external font
library is required at runtime. Horizontal stem edges use a vertical hint map;
vertical stems are retained but are not independently snapped on the X axis.
Stem darkening and synthetic bold are disabled.

## Placement and ownership

The shared PostScript page adapter rounds the transformed text-space Y axis to
an integer pixel size. It includes FontMatrix scaling, then applies checked
16.16 FontMatrix and text/device transforms. FontMatrix translation is composed
with text placement before rounding the final origin to 1/64 pixel. Rotation,
reflection, shear, unequal scales and fractional origins use this same path.
Finite singular transforms retain the existing unfitted path.

Composite base and accent programs have separate hint contexts. Their offsets
are applied before fitting; nested composites are rejected. Parent charstring
advances are retained. PDF Widths, spacing, rise, horizontal scaling and text
matrices continue to control text placement rather than fitted glyph widths.
The embedded font's PaintType does not override PDF text rendering mode, as
required by ISO 32000-1 section 9.9.

Each draw owns its fitted outline. It does not cache device-space geometry in
the font-space cache. Fills, strokes and deferred text clipping share the same
fitted path. Open contours remain open for stroking, and logical charstring
current-point records do not create painted segments. Stroke and clip coverage
remain binary. Forms inherit the option, including those with local fonts.

## Bounds and errors

The page adapter admits at most four million work units from the shared page
budget for decoding, fitting, component copies and transforms. It returns unused
work, but does not refund work already spent. The core retains its coordinate,
scale, stem, event and segment limits.

Unresolved or invalid private parameters used by this profile, allocation
failure, transform overflow and budget exhaustion fail the draw and free partial
results. Invisible text, zero text size and zero horizontal scale skip fitting.
The default unhinted path remains available when a font uses unsupported computed
hint parameters. It is not a silent fallback for a failed explicitly requested
fit.

## Tests

`make test-pdf-type1-page-hinting` checks PDF width overrides, composite accents,
text spacing, FontMatrix equivalences, fractional placement, all text modes,
stroke styles, deferred clipping, Form-local fonts, invalid options and Sixel
output. It also checks normal, mixed-case and extensionless filenames.

The focused suite has 153 page/API/CLI checks and 729 allocation/cache checks.
With the optional comparison engine available, it adds 30 independent grayscale
page matches. A local run with 75 installed PFB fonts increased the totals to
1,613 page/API/CLI checks and 1,490 independent grayscale page matches. Two fonts
lacked the selected character names and contributed no comparison pages. The
1,490 page comparisons passed with engine versions 2.13.2 and 2.13.3.

    python3 scripts/test_pdf_type1_page_hinting.py bin/test_pdf_pages bin/test_pdf_clip_oom bin/cupidimage --fonts /path/to/pfb/fonts

Stroke and clipping cases use independently obtained fitted outlines through the
native vector paths; they do not establish independent stroke-raster parity.
Unusual FontMatrix cases compare equivalent PDF transforms, rather than treating
another font loader's matrix normalization or offset truncation as PDF rules.
The standalone core has separate complete-outline and glyph-bitmap comparisons.

`assets/pdf/native-type1-hinting.pdf` is an owned visible sample, regenerated by
`scripts/generate_pdf_type1_page_hinting_fixture.py`. Its full page raster remains
decoded-unverified. The comparison tools accept `--pdf-type1-hinting` and keep
hinted ratings separate from unhinted ratings.

## Remaining scope and references

Computed PostScript dictionaries, inherited definer aliases, broader OtherSubrs,
flex policy, stem darkening, synthetic bold, fractional private parameters and
larger fitting ranges still need work. These tests establish the selected profile,
not complete Type 1 or PDF rendering conformance.

The governing rules are ISO 32000-1 sections 9.3, 9.4, 9.6 and 9.9, the
[Adobe Type 1 Font Format](https://adobe-type-tools.github.io/font-tech-notes/pdfs/T1_SPEC.pdf),
and the [PostScript Language Reference](https://www.adobe.com/jp/print/postscript/pdfs/PLRM.pdf).
See the [PDF standards guide](pdf-standards.md) for the broader specification set.

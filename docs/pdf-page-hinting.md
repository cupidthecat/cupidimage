# PDF TrueType page hinting

`--pdf-tt-hinting` enables the native legacy TrueType instruction profile for
page glyphs. The API equivalent is `cupidimage_pdf_options.truetype_hinting = 1`.
Combine it with `--pdf-text-aa` for grayscale fill coverage. Both options default
to zero, so existing callers and asset oracles retain their previous rendering.

The option applies to supported embedded and substitute TrueType programs. It
executes font/preparation/glyph instructions and uses the resulting device
outline for fill, stroke and text clipping. CFF, Type 1 and bitmap glyphs keep
their existing paths. Stroke and clip coverage remain binary.

## Sizing and placement

The grid-fitting stage uses a uniform size derived from the transformed glyph
Y-axis. Pixels per em are rounded to the nearest integer, with a minimum of 1 and
a maximum of 32,767. A checked 16.16 affine transform then applies the remaining
scale, reflection, rotation or shear. Matrix coefficients truncate toward zero;
origin coordinates round to 1/64 pixel, with halfway values rounded away from zero.
The horizontal phantom origin is removed before that transform.

The configured `MPS` value uses the transformed physical point size at the
renderer's 96-dpi resolution. It is rounded to positive 26.6 units. That convention
is tested separately from legacy comparison engines that report projected integer
ppem for this instruction. Those engines' differing `MPS` results are not counted
as agreement. See the official [instruction definitions](https://learn.microsoft.com/en-us/typography/opentype/spec/tt_instructions).

PDF Widths, MissingWidth, CID metrics and text-state operators still determine
advancement. Hinted phantom advances do not replace them. Empty glyphs remain
outline-less, and invisible or zero-scaled text does not execute glyph instructions.

## Lifetime and limits

A page keeps at most one prepared font/size/profile instance. Forms, patterns and
soft-mask contexts share it. Switching the key releases the old instance. Font
programs have explicit internal ownership references, so a Form-local program
cannot be freed while cached instruction bodies still borrow its bytes. The page
releases the cache on success and failure. Returned device outlines are owned
copies, independent of cache eviction.

Preparation, private-state restoration, glyph decoding, instruction execution and
shape copies consume the shared page work budget. Each preparation or glyph call
admits at most one million instruction/geometry work units. Declared initialization
and state-copy costs are charged separately. Invalid programs, exhausted work,
allocation failure and unrepresentable transforms fail the load; they do not emit
a partial glyph or silently fall back to a different hinting policy.

Eviction rebuilds preparation state. Glyph programs must initialize twilight points
before accessing them, as described in the [TrueType font-engine manual](https://developer.apple.com/fonts/TrueType-Reference-Manual/RM02/Chap2.html).
This cache is not a promise to reproduce arbitrary cross-glyph dependencies in
malformed programs.

## Qualification

`make test-pdf-page-hinting` includes:

- 1,188 frame, budget, ownership and retained-output checks;
- 102 core page/API/CLI checks when the optional comparison engine is absent;
- 978 allocation/cache/eager-surface checks, including Form-local font lifetimes;
- 60 independent authored grayscale bitmaps, with simple/composite glyphs and
  multiple sizes, origins and affine transforms;
- 144 independent pinned Latin bitmaps with engine 2.13.3 or newer;
- independent device-outline checks for stroke and deferred clipping.

The complete target currently reports 314 page checks with engine 2.13.3.
Older engines still run the authored comparisons, but skip the pinned Latin bitmap
sweep because their initial CVT scaling differs. Separate tests compare physical
`MPS` values with literal displacement programs and check cache reuse when two
point sizes round to the same ppem. Unsupported instructions and a nonterminating
glyph fail transactionally. CID horizontal/vertical placement and changed phantom
advances have dedicated cases.

The owned font fixture is generated by `scripts/generate_pdf_page_hinting_font.py`
using FontTools, with fixed timestamps. `assets/pdf/native-truetype-hinting.pdf`
is a visible sample built by `scripts/generate_pdf_page_hinting_fixture.py`.
Its complete raster is decoded-unverified; the focused cases above provide the
pixel evidence.

## Remaining boundaries

This is a selected legacy profile, not complete TrueType or PDF rendering parity.
Modern subpixel instruction policies, variation behavior, dropout scan conversion,
Type 1 grid fitting, fractional clipping and full stroke/combined-paint coverage
remain unfinished. CFF has its own [bounded page option](pdf-cff-page-hinting.md). The [VM](pdf-truetype-vm.md), [loader](pdf-truetype-loader.md) and
[coverage](pdf-coverage.md) guides list the narrower contracts and known differences.
